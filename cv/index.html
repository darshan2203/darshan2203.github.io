Hybrid product search

Jul 2024 – Feb 2025
Dense retrieval · contrastive learning · PyTorch · AlloyDB · Solr · A/B testing
  • Led the design and launch of Target's first hybrid search system, which runs lexical and semantic retrieval in parallel on every search. The work is the basis of a U.S. provisional patent application (first-named inventor) and an arXiv paper (co-first author).
  • Built the semantic channel from scratch: selected the embedding model and fine-tuned a dual encoder on about 20 million query–product pairs labeled from purchases, add-to-carts and clicks, using hard negatives and a bidirectional contrastive loss. Field markers and field masking keep it robust to incomplete catalog data.
  • Added adaptive precision control, using named-entity recognition and a query classifier to remove off-target vector results (precision@1 from 0.890 to 0.929), and weighted result interleaving, which outperformed reciprocal rank fusion on result lists with little overlap.
  • Four-week online A/B tests against lexical-only search: CTR +0.97%, conversion +0.98%, demand per visitor +1.10%, and about 50% fewer zero-result searches. Serving 100% of search traffic since February 2025.

Personalized retrieval

2025
Two-tower models · attention · PyTorch · Vertex AI · PySpark · Redis
  • Moved personalization into the retrieval layer with user, query and item towers. Query-guided attention over a shopper's real-time, short-term and long-term behavior produces a user-aware query vector for a dedicated personalized retrieval channel.
  • Designed multi-layer cross-attention between the query and each user feature, and an adaptive weighting layer that learns how much purchases, clicks and add-to-carts should each count.
  • Built multi-GPU training on Vertex AI, PySpark pipelines for user-history training data and a Redis feature store for near-real-time user embeddings. The best variant improved Recall@K, NDCG and MRR offline.

Automated relevance labeling and precision control

2025 – present
Agentic LLM pipelines · LLM fine-tuning · knowledge distillation · cross-encoders
  • Designed a three-stage system for four-class search relevance, where each stage covers what the one before it cannot:
    1. Agentic labeling: state-of-the-art LLMs in an agentic pipeline produce a first-generation relevance dataset with reasoning for every label. Highest quality, but too slow and costly for all traffic.
    2. In-house relevance LLM: fine-tuned on that reasoning data, it labels at scale for evaluation and training at much lower cost, with data kept in-house.
    3. Online student: a lightweight cross-encoder or shared bi-encoder, distilled from the in-house LLM, filters off-target results at query time within the search latency budget.
